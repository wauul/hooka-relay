# 2026-09-22 — SDK packages and API contract

## Context
The event-ingestion API is shared by Node and Python integrations. Maintaining request/response types independently risks drift. Both SDKs need independently publishable artifacts without changing dashboard or worker layout.

## Decision
Keep packages in `packages/node` and `packages/python`. Hand-author an OpenAPI 3.0 contract beside the existing handlers; generate the SDK event models from it with a small checked generator. CI regenerates and rejects drift. Use native fetch/urllib with explicit timeouts, no automatic retries, and no redirect credential forwarding. Verify signatures through the official Standard Webhooks libraries. SDK examples explicitly distinguish volatile demonstration queues from durable receiver inboxes.

Serve a self-hosted Swagger UI on the existing docs page because its free distribution supports trying requests. Authorization stays in page memory, external spec validation is disabled, and existing CSP remains intact. No paid documentation or SDK-generation service is required.

## Consequences
One repository review can update server, contract, and both generated models. The small generator intentionally supports only the event model subset and fails on unsupported types. Maintainers must keep contract descriptions aligned with route behavior. Package publishing is separate from deployment; bootstrap credentials should be revoked after package-scoped trusted publishing is configured.
