# Pattern diagnosis and synthetic verification

## Context
An isolated failure hides changes across attempts. A diagnostic suggestion is more useful when the operator can test a fix, but a separate test HTTP client would bypass leases, SSRF checks, signing rotation and receiver protection.

## Decision
Derive deterministic facts from at most 20 recent HTTP attempts, including successes. Label an unknown earlier failure start as a lower bound. Give the existing advisory Groq call these facts and at most eight short response excerpts; keep the existing trigger/cooldown and bound completion tokens. Display current observed evidence separately from AI hypotheses and historical diagnoses.

Add an authenticated, same-origin endpoint test action for all workspace roles. Internally target one endpoint through the existing ingest transaction and durable outbox. The explicit target is never accepted by public ingestion. Use a fixed `hooka.test` payload, enforce registered schemas and shared endpoint/application/IP admission budgets, and reject pause/open circuits rather than bypassing them. Worker signing, secrets, transforms, throttles, leases, SSRF validation, retries and circuit decisions remain unchanged. The test UI watches the normal delivery log for 30 seconds.

## Consequences
This MVP supports diagnosis and operator-driven verification, not autonomous changes. Tests make real requests to the configured destination and can retry or affect the circuit just like normal events. A fixed synthetic body cannot satisfy every business schema or transform; the existing application test form remains available for custom payloads. Groq outages do not remove deterministic evidence or prevent deliveries. No new paid provider, infrastructure or automatic developer email is introduced.
