# 2026-09-22: Pull backlog and durable recovery

## Context
Long outages can exceed retry windows. Extending default retries would change delivery timing and consume resources for every endpoint.

## Decision
Add a tenant-scoped, cursor-paginated pull API and durable recovery jobs. Reuse per-event replay locks/generations. Exclude pending/successful newer generations and rate-control job batches.

## Consequences
Receivers recover explicitly after outages. Events never enqueued are matched against current subscriptions; historical subscription snapshots are not invented.
