# UI audit — 22 September 2026

Recorded before UI implementation, against production auth/email release `8c74910`.
Browser checks used 375 × 812, 768 × 900/1024 and 1280 × 900 viewports, DOM/layout measurements and screenshots. Populated review application, successful synthetic delivery, empty states, and account/error pages were inspected. No document-wide horizontal overflow was observed in the sampled states; tables/code scroll within their own regions. Loading captures are not evidence of completed data loading. Verification after fixes must cover loaded states and interaction results separately.

| Page/surface | Observed issues / required improvement |
| --- | --- |
| Shared navigation | Workspace and profile links work, but team/settings are weakly discoverable. Workspace selection can redirect a newly signed-in account away from its intended page. No theme/language controls. Tablet sidebar consumes useful width. |
| Dashboard | Application cards expose noisy internal IDs. Support/contact float over lower content. Loading shows a zero count before data arrives. Application creation/empty guidance already exists and should be preserved. |
| Application | Security key, portal, schemas and catalog precede endpoints/test events in one long page. Add Overview, Endpoints, Events & Logs, API Keys & Security and Settings navigation; team belongs in shared navigation. Keep one-time key disclosure state when switching sections. |
| New endpoint | Basic onboarding and built-in receiver guidance work. Technical helper copy is small. Use consistent field spacing and add concise subscription guidance without changing routing. |
| Endpoint | Pause/delete/signing/configuration/replay dominate before delivery stats. Buttons lack action icons; delete has insufficient visual distinction. Move configuration/security to sections; keep stats/testing/logs discoverable. Circuit states need concise inline explanations. |
| Event details | Successful attempt and raw request/response data render. Code is contained but small; preserve copy and replay. Long IDs should wrap without changing copied values. |
| Missed events/backlog | Heading inherits body-sized reset typography. Filter explanation is dense. Empty stored-events panel lacks guidance. Recovery controls need clearer grouping/icons. |
| Workspace/team | Existing spacing is better than dense application pages, but workspace creation consumes primary space; rename/invite/member/destructive controls need consistent icons, hierarchy and empty pending-invite guidance. |
| Profile | Requested tagline is present. No primary heading (retain the requested copy without restoring the removed slogan). Blank profile panel while loading; linked providers still say Link rather than indicating connected status. Email is correctly read-only. |
| Login | OAuth lacks brand icons. Search distracts from authentication. Recovery links compete with primary action; retain both. |
| Signup | Same OAuth issue; forgot-password link is unnecessary here. Confirmation requirement should be stated before submission. |
| Forgot password | Body-sized heading, large empty vertical gap and no panel hierarchy. Generic response/security behavior must stay unchanged. |
| Resend verification | Same typography/layout issue as recovery; preserve generic response. |
| Reset password | Missing-token error says request an email below, but only links to sign-in. Needs direct new-reset link, consistent heading and password visibility control. |
| Verify email | Missing-token recovery link works, but heading/card hierarchy inconsistent with invitations. Keep explicit confirmation so scanners do not consume links. |
| Invite accept | Invalid-token screen is clear and contained. Keep polished card and explicit accept/refuse; match common theme/language and OAuth/action icons. Valid invite state requires post-change flow verification. |
| Customer portal | Brand is plain text rather than shared wordmark. Heading hierarchy collapses to body size. Empty endpoints/logs need actionable guidance. Refresh/pause/delete lack consistent icons. Browser-bound ownership notice must remain prominent. |
| Status | Headings are body-sized; incident and metric hierarchy weak. Existing explanation correctly distinguishes receiver outcomes from platform uptime; preserve it. Refresh needs icon. |
| Documentation | Narrative theme is consistent, but Swagger is a white island in dark mode. Copy controls below 40px height. Need local contents navigation, consistent explorer surfaces and usable narrow operation summaries. |
| Support widget | Plain rectangular launcher; no message-bubble hierarchy/animated transition/thinking indicator. Mobile panel nearly touches the left edge. Contact widget competes with it. Scope/privacy copy is useful and must remain. |
| Contact/search/dialogs | Get in touch cannot be dismissed. Keep existing dialog focus management. Action icons must be decorative next to meaningful labels, not replace accessible names. |
| Privacy | Headings and paragraphs run together with reset typography; improve measure, section spacing and return navigation. |
| 404/loading | 404 content works but duplicates search; loading hierarchy varies. Keep useful recovery links and reduced-motion behavior. |
| Root / landing | Existing root is a redirect, not a public marketing page. Build landing last using settled design tokens, then audit all three widths. |

## Implementation checklist

- [ ] Shared color/spacing/type tokens, accessible action icons, theme and English/French preferences.
- [ ] Navigation/sections without rewriting backend logic or losing unsaved/key state.
- [ ] Empty/loading/error states and recovery links.
- [ ] Support bubbles, thinking state, mobile positioning; dismissible contact.
- [ ] Landing page last, custom lightweight SVG flow and actual docs/package links.
- [ ] Post-change desktop/mobile flows, keyboard focus, reduced motion, CI and deployment.
